# Лаба 2: CNN на CIFAR-10 — что происходит и как отвечать

Смысл простыми словами: собираем свёрточную нейросеть (CNN), которая смотрит на цветную картинку 32x32 и угадывает, что на ней из 10 классов (самолёт, машина, птица, кошка, олень, собака, лягушка, лошадь, корабль, грузовик). Свертка — это маленькое «окошко» (фильтр), которое ездит по картинке и ищет свои примитивы: линии, уголки, пятна. Первые слои находят простые фигуры, последние — целые объекты. Все 4 пункта методички закрыты в `lab2_cnn_cifar10.ipynb`.

## По пунктам — что говорить

**П.1 Данные:** `keras.datasets.cifar10.load_data()` → `50000 картинок 32x32x3 для обучения / 10000 для теста`. Показываем по 3 примера на каждый класс. Предобработка: делим на 255 (яркость `0-255` → `0-1`). Flatten НЕ делаем — в отличие от MLP из лабы 1, CNN работает с двумерными картинками: иначе потеряем пространственную структуру, которую свёртка как раз использует.

**П.2 Архитектура (`build_cnn`):**

```
Input(32,32,3)
-> [Conv2D(32,3x3,relu,same) -> MaxPool(2x2)]
-> [Conv2D(64,3x3,relu,same) -> MaxPool(2x2)]
-> [Conv2D(128,3x3,relu,same) -> MaxPool(2x2)]
-> Flatten -> Dense(128,relu) -> Dropout(0.3) -> Dense(10,softmax)
```

Сверточный слой = много маленьких фильтров, каждый ездит по всей картинке ОДНИМИ И ТЕМИ ЖЕ весами (это и даёт экономию параметров: фильтр 3x3 имеет 27 весов, а Dense-слой, который соединил бы каждый пиксель с каждым — миллионы). `padding='same'` — конгруэнтная свертка: край заполняется нулями, размер картинки не меняется, свертка уменьшает только MaxPooling (32→16→8→4). Число фильтров растёт вглубь (32→64→128): чем глубже, тем больше «осмысленных» комбинаций признаков.

Формула параметров сверточного слоя (надо уметь выписать):

$$P = (M_1 \cdot M_2 \cdot K_{in} + 1) \cdot K_{out}$$

- `M1 x M2` — размер ядра, `K_in` — каналов на входе, `K_out` — число фильтров, `+1` — bias на каждый фильтр.
- Для нашей сети: conv1 = (3·3·3+1)·32 = **896**, conv2 = (3·3·32+1)·64 = **18496**, conv3 = (3·3·64+1)·128 = **73856**, dense1 = (4·4·128+1)·128 = **262272** (после трёх пулингов карта 4x4x128 → вектор 2048), dense2 = (128+1)·10 = **1290**. Итого **356 810** — сверяется с `model.summary()` / `count_params()`, в ноутбуке стоит `assert`.

**П.3 Обучение:** `EPOCHS=25, batch=128, validation_split=0.2` (традиционные 20% на валидацию). `ModelCheckpoint(monitor='val_acc', save_best_only=True)` — callback, который после каждой эпохи смотрит точность на валидации и сохраняет веса в файл ТОЛЬКО если она лучше всех прошлых — в конце обучения в файле лежат лучшие веса, а не последние. Модель целиком сохраняем через `model.save('cnn10_model.keras')`, при загрузке `load_model` + `load_weights('best_cnn10.weights.h5')` — в задании прямо сказано «при загрузке обученной модели не забывать загружать в нее лучшие сохраненные веса». Кривые loss/acc по эпохам — как обычно: обе падают/растут, зазор train/val небольшой.

Фактические цифры прогона: `train acc 0.3731 -> 0.8958`, `val acc 0.5012 -> ~0.72` (лучший `val_acc 0.7297` на 20-й эпохе — он и уехал в чекпоинт), `val_loss 1.38 -> 0.89`, дальше начинает расти (лёгкое переобучение после ~12-й эпохи, Dropout 0.3 его сдерживает). На тесте `evaluate: loss=1.0042 acc=0.7213`.

**П.3 Тест:** evaluate на 10000 тестовых картинок, точность по классам через маску `(pred[y_test==c]==c).mean()`, для каждого класса выводим 2 картинки, которые сеть проклассифицировала неверно (`np.flatnonzero((y_test==c) & (pred!=c))[:2]`), заголовок `true -> pred`. Записываем проценты в таблицу — это колонка `Ini_10class`. Сложные классы — `cat 0.50` и `deer 0.59` (животные похожи), простые — `ship 0.85` и `horse 0.83`.

**П.4 Transfer Learning:** 4 шага из задания.
1. Удаляем 2 класса из обучающей выборки (у нас `cat` и `dog` — произвольные, разные для разных студентов), метки перенумеровываем в 0..7 (`old2new = {0:0, 1:1, 2:2, 4:3, 6:4, 7:5, 8:6, 9:7}`).
2. Обучаем ту же архитектуру с выходом на 8 нейронов на 8-классовой выборке.
3. Смотрим точность по классам (`Ini_8class` — считается на 8 тестовых классах).
4. **Перенос:** `model8.pop()` трижды снимает `Dense(8)`, `Dropout`, `Dense(128)` — оба полносвязных слоя из задания. `base.trainable = False` замораживает ВСЕ оставшиеся слои (3 свёрточных блока + Flatten — 93248 параметров, которые больше не учатся). Сверху — новая голова `Dense(128,relu) -> Dropout -> Dense(10,softmax)` (263562 обучаемых параметров). Компилируем, обучаем на ПОЛНЫХ данных (10 классов), классифицируем тест (`TransferLearning_10class`).

Что показывает таблица: transfer learning доучивает только «голову», а свёрточные признаки, выученные на 8 классах, переиспользуются. Для 8 «старых» классов точность обычно близка к обученной с нуля, для 2 «новых» (cat/dog) — заметно ниже: замороженные фильтры их никогда не видели. Зато обучение быстрее и требует меньше данных.

Итоговая таблица нашего прогона (средние): `Ini_10class = 0.7213`, `Ini_8class = 0.7946` (по 8 классам), `TransferLearning_10class = 0.7304`. По классам:

## Контрольные вопросы — готовые ответы

**1. Выражение для свертки в СНС, отличия от классической, valid/same.**

$$s_{n_1 n_2} = \sum_{m_1}\sum_{m_2}\sum_{k} x_{n_1+m_1,\, n_2+m_2,\, k}\; w_{m_1,\, m_2,\, k}$$

В классической свертке ядро прикладывается «в обратном порядке» (для коммутативности). В СНС под словом «свертка» понимают перекрёстную корреляцию — ядро без разворота. Суммирование по третьей координате (каналам) идёт полностью, размер ядра по глубине = числу входных каналов. **Корректная (valid):** ядро только в позициях, где оно целиком помещается — выход меньше входа: `(N1-M1+1) x (N2-M2+1)`. **Конгруэнтная (same):** вход дополняется нулями (padding), пространственный размер выхода = входу.

**2. Характеристики сверточного слоя.** Метапараметры: размеры фильтров `M_r1 x M_r2`, их количество `K^l`, шаги `S1, S2`, параметры дополнения `P1, P2`, функция активации. Обучаемые параметры: $P = \sum_r (M_{r,1} \cdot M_{r,2} \cdot K^{l-1} + 1)$ — по слагаемому на каждый фильтр, `+1` — bias.

**3. Поточечная свертка 1x1.** Ядро 1x1xK: $s_{n_1,n_2,r} = \sum_k y_{n_1,n_2,k}\, w_{0,0,k} + b_r$ — скалярное произведение вектора каналов в КАЖДОЙ пространственной точке. Смысл: примитивный коррелятор по вектору признаков точки или проекция тензора в новое пространство (сменить число каналов без изменения HxW). Применение: «бутылочное горлышко» — сжать каналы дёшево, в Inception-блоках.

**4. Слой пулинга.** max: $y_{n_1,n_2,k} = \max_{(m_1,m_2)\in D} y_{n_1+m_1,\,n_2+m_2,\,k}$; average: то же с $\frac{1}{|D|}\sum$. Работает независимо по каждой карте признаков. Параметров НЕТ — только метапараметры (шаги, тип, размер окна). Вместе с субдискретизацией (stride) уменьшает пространственный размер: max-pool 2x2 с шагом 2 сжимает вдвое. Смысл: небольшие сдвиги объекта не меняют ответ (инвариантность) + меньше вычислений дальше.

**5. Полносвязный слой в СНС.** Ставится в конце, когда пространственная информация почти исчерпана (карта маленькая), а основная размерность «перешла» в каналы. Перед ним `Flatten`: тензор N1xN2xK → вектор N1·N2·K (у нас 4x4x128 → 2048). Формула обычная: $y = f(Wx+b)$. Полносвязные слои можно представить как свёрточные с ядром 1x1 — тогда говорят о полностью свёрточной сети.

**6. Приёмы в СНС.** *Bottleneck:* сжать вход в маленькое представление, потом развернуть обратно — экономия вычислений (пример: conv 3x3x256 → 1x1x64 → 3x3x64 → 1x1x256 в ResNet). *Передача информации (skip-connections):* (a) ResNet — $y = F_W(x) + x$, тензор складывается с входом; (b) DenseNet — конкатенация по глубине с входом (после таких конкатенаций ставят 1x1-свёртку для снижения глубины). *Нормализация:* BN/LN стабилизируют обучение; Dropout после свёрток нецелесообразен (шумит карты признаков) — применяют после Flatten, либо SpatialDropout2D, который отключает целые карты.

**7. Типовая архитектура.** `INPUT -> [[CONV -> RELU]*N -> POOL?]*M -> [FC -> RELU]*K -> FC -> SOFTMAX`. Сначала пары «свёртка+пулинг» (у нас N=1, M=3), потом развёртка и классическая полносвязная часть. Выход — softmax по числу классов. Данные, характеризующие CNN: архитектура, число параметров (~размер сети), число операций (~нейронные связи), значение критерия качества.

## Частые вопросы препода — короткие ответы

### Почему фильтров 32 → 64 → 128, а не наоборот?
По мере углубления поле восприятия фильтра растёт (3x3 → после пары слоёв эквивалент 5x5, 7x7...), комбинаций осмысленных признаков становится больше — надо больше фильтров, чтобы их покрыть. Одновременно пространство сжимается пулингом (32x32 → 4x4), так что рост числа каналов не разрывает бюджет вычислений. И это требование методички: 32, 64, 128.

### Почему Dense-часть такая маленькая (один скрытый слой на 128)?
Задание так требует: Flatten → полносвязный (relu) → Dropout → выход. По правилу лабы — не усложняем. 262272 параметра из 356810 вообще сидят в Dense(2048→128): это нормально, «классифицирующая» голова обычно тяжелее сверточной части у маленьких сетей.

### Что делает ModelCheckpoint и почему без него плохо?
После каждой эпохи проверяет `val_acc`; если она лучшая за всё обучение — перезаписывает файл весов. Без него в конце обучения остались бы веса ПОСЛЕДНЕЙ эпохи, а переобучение могло начаться раньше — и мы бы сдали сеть хуже, чем она была в середине.

### Чем .keras-файл отличается от .weights.h5?
`.keras` — модель целиком (архитектура + веса + состояние), открывается `keras.models.load_model()`. `.weights.h5` — только веса (числа), их можно залить только в УЖЕ собранную такую же архитектуру через `load_weights()`. В лабе сохраняем оба: модель — чтобы использовать дальше, веса — чтобы гарантированно достать лучшие (checkpoint).

### Почему удаляем именно Dropout вместе с Dense при pop(), если он не полносвязный?
Потому что pop() снимает слои с конца: после снятия Dense(8) следующий слой с конца — Dropout, и только потом Dense(128). Снять «через один» нельзя. Задание требует убрать два ПОЛНОСВЯЗНЫХ слоя (выходной и скрытый) — они убраны, а новый Dropout входит в новую голову. Итог тот же: base = свёртки + Flatten, голова = Dense(relu) + Dropout + Dense(softmax).

### Почему замороженную базу нельзя обучать, если она уже хорошая?
Можно, но тогда это уже не тот механизм transfer learning из задания: смысл в том, чтобы проверить, что признаки свёрточных слоёв УНИВЕРСАЛЬНЫ. Плюс дообучение всей сети на 10 классов — это просто повторение п.3, сравнение потеряло бы смысл. Замороженные слои не портят уже выученные признаки (и учатся быстрее — меньше параметров).

## Функции — подробно и просто

Сквозная картинка размерностей: картинка `(32,32,3)` из целых `0-255` → дроби `0-1` → батч `(B,32,32,3)` → после трёх блоков `(B,4,4,128)` → Flatten `(B,2048)` → Dense `(B,128)` → вероятности `(B,10)` → номер класса.

### 1. Свои функции

**`build_cnn(dropout=0.3, n_classes=10)` → готовая модель**
Простыми словами: конструктор сети из задания. `n_classes` нужен для п.4 — одна и та же архитектура с выходом на 8 или на 10.

- Что внутри: 3 пары `Conv2D(фильтры, 3, relu, same) + MaxPooling2D()` → `Flatten` → `Dense(128,relu)` → `Dropout` → `Dense(n_classes, softmax)` → `compile`.
- Что сказать преподу: «padding same — карта не сжимается сверткой, сжимается только пулингом; relu не даёт градиенту затухать; softmax превращает 10 чисел в вероятности».

**`count_cnn_params(n_classes=10)` → число (int)**
Калькулятор параметров без сети, ручка для защиты формулы. Свертка: `(M1*M2*K_in + 1) * K_out`; Dense: `(fan_in+1)*fan_out`. Сверка через `assert model.count_params() == count_cnn_params()`.

### 2. Загрузка данных

**`keras.datasets.cifar10.load_data()` → две пары (картинки, метки)**
- Выход: обучение `(50000,32,32,3) + (50000,)`, тест `(10000,32,32,3) + (10000,)`. Метки 0-9, имена в `CLASS_NAMES`.
- `astype('float32')/255.0` — дроби 0-1. `reshape` НЕ делаем (в отличие от MNIST-MLP): Conv2D принимает полноразмерные картинки.
- Метки приходят `(N,1)` → делаем `(N,)` через `reshape(-1)`.

### 3. Слои

**`layers.Conv2D(K, 3, activation='relu', padding='same')` — главный слой**
Простыми словами: K окошек 3x3, каждое ездит по картинке и в каждой позиции считает взвешенную сумму окрестности (перекрёстная корреляция). Выход — K карт признаков.

- Вход `(B,32,32,3)` → выход `(B,32,32,32)` при same: высота/ширина не меняются, глубина = числу фильтров.
- Веса ОДНОГО фильтра общие для всех позиций картинки — локальность + общие веса = на порядки меньше параметров, чем у Dense.
- Параметры: `(3*3*K_in + 1) * K_out`.

**`layers.MaxPooling2D()` — сжатие**
Окно 2x2, из каждого окна берётся максимум, шаг 2 → карта сжимается вдвое. Параметров 0. max-пулинг оставляет самый сильный отклик фильтра в окрестности — мелкие сдвиги не влияют.

**`layers.Flatten()` — развёртка**
`(B,4,4,128)` → `(B,2048)`, просто выкладывает кубик в строку. Мост между свёрточной и полносвязной частью.

**`layers.Dense / Dropout / softmax`** — как в лабе 1: Dense учит (y=f(Wx+b)), Dropout маскирует нейроны при обучении (в тесте выключен), softmax = вероятности.

### 4. Обучение и сохранение

**`callbacks.ModelCheckpoint(path, monitor='val_acc', save_best_only=True, save_weights_only=True, mode='max')`**
Простыми словами: наблюдатель, который после каждой эпохи решает, писать ли веса. `monitor='val_acc'` — следим за точностью на валидации; `mode='max'` — чем больше, тем лучше; `save_best_only` — писать только при рекорде; `save_weights_only` — писать только числа весов, без архитектуры.

**`model.save('...keras')` / `keras.models.load_model(...)`** — модель целиком в файл и обратно.

**`model.load_weights('...weights.h5')`** — залить сохранённые лучшие веса в собранную модель. В лабе: load_model → load_weights → evaluate/predict.

**`fit(..., validation_split=0.2, callbacks=[ckpt])`** — то же, что в лабе 1: 80/20, история в `hist.history` (`loss/acc/val_loss/val_acc` по эпохам).

### 5. Оценка и Transfer Learning

**Точность по классам:** `per_class[c] = (pred[y_test==c] == c).mean()` — маска «тестовые картинки класса c», доля верных внутри неё. Это и есть «процент правильной классификации» из таблицы задания.

**Поиск ошибок:** `np.flatnonzero((y_test==c) & (pred!=c))[:2]` — индексы первых двух ошибок класса c, показываем с подписью `true -> pred`.

**Удаление классов:** `np.isin(y_train_full, kept)` — маска «метка в списке оставшихся»; `old2new` — словарь перенумерации (метки должны стать 0..7 подряд, иначе sparse-кроссэнтропия упадёт).

**`model.pop()`** — снимает ПОСЛЕДНИЙ слой модели. Три вызова подряд: Dense(8) → Dropout → Dense(128). После каждого pop() модель «пере-строится», её можно сразу использовать.

**`base.trainable = False`** — заморозка: у всех слоёв базы `trainable=False`, их веса исключаются из градиентного спуска (видно в `summary()`: Trainable params = только голова, Non-trainable = вся база). НОВАЯ модель собирается как `Sequential([base, Dense(relu), Dropout, Dense(softmax)])`.

**Компиляция новой модели обязательна** после сборки и заморозки — без `compile` Keras не знает, что минимизировать.
